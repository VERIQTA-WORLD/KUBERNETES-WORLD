# 3. Why Use a Local Lab?

Learning Kubernetes directly in production would be dangerous.

Learning only from diagrams is insufficient.

A local lab gives you somewhere to:

```text
Create

Delete

Break

Repair

Experiment

Inspect

Repeat
```

without risking a production environment.

You need an environment where failure is expected.

---

# 4. What Makes a Good Learning Environment?

A good Kubernetes lab should be:

```text
Disposable

Repeatable

Affordable

Easy to inspect

Easy to break

Easy to rebuild

Isolated from production
```

If you completely destroy today's cluster, you should be able to rebuild it.

That is a feature, not a failure.

# 10. Verify Docker

If Docker is already installed, run:

```bash

```

Purpose:

```text

```

You may also run:

```bash

```

Purpose:

```text

```


```bash

```

and:


# 11. Common Docker Failure

You may see an error indicating that the Docker daemon cannot be reached.

This usually means:

```text
Docker CLI exists
↓
Docker engine unavailable
```

Possible causes:

```text
Docker Desktop not started

Docker service stopped

Permission problem

Wrong Docker context

Socket problem
```

Do not reinstall Kubernetes immediately.

Fix the lower layer first.

# 13. localhost

You will frequently encounter:

```text
127.0.0.1
```

and:

```text
localhost
```

These refer to loopback access on the local host.

Local Kubernetes tools may expose services or API endpoints through localhost or locally forwarded ports.

Do not confuse:

```text
localhost on your laptop
```

with:

```text
localhost inside a container
```

or:

```text
localhost inside a Pod.
```

Each network namespace can have its own loopback environment.

This distinction becomes very important later.

# 24. Prerequisite 8: Memory

Kubernetes components and workloads need RAM.

Your local container provider also needs memory.

If memory is too constrained, you may experience:

```text
Slow cluster startup

Containers killed

Pods failing

Node instability

Docker instability
```

For a small learning cluster, several gigabytes of available RAM are normally needed.

Multi-node clusters and realistic workloads require more.

Do not allocate every byte of system memory to your lab.

Your host operating system also needs memory.

---

# 25. Check Memory on Linux

Run:

```bash
free -h
```

Example categories include:

```text
total
used
free
available
```

Pay particular attention to available memory rather than assuming the `free` column alone represents all usable capacity.

---

# 26. Check Memory on macOS

# 27. Check Memory on Windows

Always remember the host system exists underneath the cluster.

# 48. kubectl Version Compatibility

Do not blindly install an arbitrary old kubectl.

The supported version-skew rule requires `kubectl` to remain within one minor version of the Kubernetes API server.

Conceptually:

```text
API Server v1.N
```

should use a supported kubectl around:

```text
v1.(N-1)
v1.N
v1.(N+1)
```

subject to the current Kubernetes version-skew policy.

For a new lab, using a current compatible client is simplest.

---

# 49. Why Version Compatibility Matters

Kubernetes APIs evolve.

An extremely old client may not understand newer server behavior.

A very new client may expect capabilities unavailable on a much older server.

Production teams therefore manage versions deliberately.

Never adopt:

```text
"Install whatever kubectl version happens to appear first."
```

as a production standard.

# 50. LAB 1: Install kubectl on Linux

One upstream-supported method is to download the current stable binary.

For x86-64 Linux:

```bash
curl -LO "https://dl.k8s.io/release/$(curl -L -s https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl"
```

For ARM64, use the corresponding ARM64 binary from the official installation documentation.

Before copying commands, determine your architecture:

```bash
uname -m
```

Common output:

```text
x86_64
```

or:

```text
aarch64
```

Do not install an AMD64 binary on an ARM64 machine.

# 51. Verify the Linux Download

Supply-chain verification matters.

Download the matching checksum using the official Kubernetes installation instructions.

Then verify the binary against that checksum before installing it.

Do not develop the habit:

```text

↓
chmod +x
↓
sudo move
↓
trust blindly
```

Production engineering includes artifact verification.

Conceptually:

```text

↓
/usr/local/bin
/usr/bin

↓
Find kubectl
↓

```

If the binary exists in:

```text

```

but:

```text

```

is not in PATH, typing:

```bash

```

may fail.

# 149. Common Failure: Certificate Error

Possible symptom:

```text
x509
```

Do not disable TLS verification immediately.

Investigate:


# 181. kubeconfig Security

Check Linux/macOS permissions:

```bash
ls -l ~/.kube/config
```

You generally want local kubeconfig containing sensitive credentials protected from unnecessary users.

A common restrictive mode for a user-owned sensitive file is:

```bash
chmod 600 ~/.kube/config
```

But do not blindly change ownership or permissions on centrally managed configurations without understanding your environment.

---

# 182. What chmod 600 Means

For a regular file:

```text
6
↓
owner read + write

0
↓
group no permissions

0
↓
others no permissions
```

Therefore:

```text
600
```

means:

```text
Owner: read/write

Group: none

Others: none
```

This is basic Linux knowledge directly relevant to Kubernetes security.

---

# 183. Never Use chmod 777 as a Fix

Do not solve permission problems with:

```bash
chmod 777 ~/.kube/config
```

That would grant broad access.

Security rule:

```text
Understand required access
↓
Grant minimum necessary permissions
```

not:

```text
Permission error
↓
777 everything.
```

| ----------------------------------------- | -------------------------- | ----------------------------------- |
| `kubectl: command not found`              | Installation/PATH          | `command -v kubectl`, PATH          |
| kubectl client works but cluster does not | Configuration/connectivity | context, kubeconfig, endpoint       |
| Connection refused                        | API endpoint/network       | context, server, cluster, Docker    |

| Forbidden                                 | Authorization              | RBAC/permissions                    |
| kind creation fails                       | Local provider/resources   | Docker, memory, disk, logs          |
| Wrong resources appear                    | Context                    | `current-context`                   |
| Nodes NotReady                            | Node layer                 | describe node, system Pods, runtime |
| System Pod failing                        | Component/add-on layer     | describe Pod, events, logs          |

# 210. Clean Temporary kubeconfig Files

If you created:

```text
broken-kubeconfig
```

and no longer need it:

```bash
rm -f broken-kubeconfig
```

If the environment variable is still set:

```bash
unset KUBECONFIG
```

PowerShell:

```powershell
Remove-Item Env:KUBECONFIG -ErrorAction SilentlyContinue
Remove-Item .\broken-kubeconfig -ErrorAction SilentlyContinue
```

# 211. Protect Your Backup

If:

```text
~/.kube/config.part3-backup
```

contains real credentials, it is also sensitive.

Do not leave unnecessary credential copies scattered around.

Once you have confirmed your real configuration is correct and no longer need the backup, remove the lab backup safely:

```bash
rm ~/.kube/config.part3-backup
```

Only do this after verifying your active kubeconfig.

To create a safe, disposable environment for experimentation without risking production systems.

### 2. What prerequisite technologies should you understand?

```text
Git
```

Kubernetes components and workloads consume compute resources.

### 4. Why does memory matter?

The host, container provider, Kubernetes components, and workloads all require memory.

### 5. Why does disk matter?

Images, layers, logs, volumes, and node filesystems consume disk space.

# 215. Knowledge Check: Environments

### 6. What is kind?

A tool for running local Kubernetes clusters with Kubernetes nodes represented by containers.

### 7. What is minikube?

A tool for running local Kubernetes clusters for learning and development.

A tool for running K3s clusters in containers.

### 9. What is kubeadm?

A tool used to bootstrap and manage Kubernetes clusters on machines you control.

### 10. What is managed Kubernetes?

A Kubernetes offering where a provider manages some cluster infrastructure, particularly significant control-plane responsibilities.

# 218. Knowledge Check: Contexts

### 21. How do you switch contexts?

```bash
kubectl config use-context <CONTEXT>
```

### 22. Why is context awareness important?

Because the same kubectl command can operate against completely different clusters.

### 23. What is more dangerous: an unreachable cluster or silently using the wrong production context?

The wrong context can be especially dangerous because commands may succeed against the wrong environment.

### 24. Can one kubeconfig contain multiple clusters?

Yes.

### 25. Can you explicitly select a context without changing the current context?

Yes:

```bash
kubectl --context <CONTEXT> get nodes
```

# 220. Knowledge Check: Troubleshooting

### 31. `kubectl: command not found` suggests what?

Installation or PATH problem.

### 32. `connection refused` suggests what broad area?

Endpoint, cluster availability, or network/connectivity.

### 33. `Unauthorized` suggests what?

Authentication.

### 34. `Forbidden` suggests what?

Authorization.

### 35. An x509 error suggests what broad layer?

TLS/certificate trust or identity configuration.


# 221. Knowledge Check: Security

### 37. Should kubeconfig be committed to Git?

Not when it contains or references sensitive credentials. Treat kubeconfig as sensitive by default.

### 38. Should you fix kubeconfig permission errors using `chmod 777`?

No.

### 39. Why?

It grants unnecessary access and violates least-privilege principles.

### 40. Should you disable TLS verification merely because you see an x509 error?

No.

Investigate the trust failure.

```text

↓
Context
↓
Identity
↓

↓

↓
```

A professional Kubernetes engineer must always know:

```text

Which identity am I using?
```
